# Лабораторная работа №4
## Тема: Проектирование REST API

## Описание системы
Система представляет собой API для сервиса подписок на ИИ инструменты, позволяющий пользователям:
- Просматривать доступные ИИ сервисы
- Оформлять подписки
- Управлять избранными сервисами
- Оставлять отзывы

### Основные сущности

1. **Service (Сервис)**
   - Представляет ИИ инструмент
   - Содержит информацию о названии, описании, цене и функциях
   - Пример: ChatGPT Plus, Midjourney, Claude

2. **Order (Заказ)**
   - Представляет оформленную подписку
   - Связывает пользователя с выбранным сервисом
   - Содержит информацию о стоимости и статусе подписки

3. **Favorite (Избранное)**
   - Позволяет пользователям сохранять интересующие их сервисы
   - Связывает пользователя с сервисом

4. **Review (Отзыв)**
   - Содержит оценку и комментарий пользователя о сервисе
   - Привязан к конкретному сервису и пользователю

### Основные операции
1. Пользователь просматривает доступные ИИ сервисы
2. Может добавить интересующие сервисы в избранное
3. Оформляет подписку на выбранный сервис (создает заказ)
4. Может оставить отзыв о сервисе после использования

## Документация по API

### 1. Проектные решения

1. **Архитектурный стиль REST**
   - Использование стандартных HTTP методов (GET, POST, PUT, DELETE)
   - Stateless взаимодействие между клиентом и сервером
   - Единообразный интерфейс для всех endpoints

2. **Структурирование URL**
   - Использование существительных вместо глаголов
   - Иерархическая структура ресурсов
   - Пример: `/services/{id}/reviews` вместо `/getServiceReviews/{id}`

3. **Формат данных**
   - JSON как основной формат обмена данными
   - Согласованная структура ответов
   - Content-Type: application/json для всех запросов и ответов

4. **Обработка ошибок**
   - Использование стандартных HTTP кодов состояния
   - Унифицированный формат сообщений об ошибках
   - Информативные сообщения для отладки

5. **Версионирование API**
   - Подготовка к будущим изменениям
   - Возможность поддержки нескольких версий API
   - База для обратной совместимости

6. **Безопасность**
   - Валидация входных данных
   - Проверка обязательных полей
   - Защита от дублирования данных

7. **Пагинация и фильтрация**
   - Ограничение количества возвращаемых элементов
   - Возможность фильтрации по параметрам
   - Оптимизация производительности

8. **Документирование API**
   - Подробное описание всех endpoints
   - Примеры запросов и ответов
   - Описание параметров и форматов данных
